# 📡 CareerCraft Observability & Telemetry Architecture

## 1. Observability Architecture

CareerCraft implements a multi-layered telemetry and logging architecture designed to track request flow, operational performance, AI provider behavior, and system health across the application lifecycle.

```text
Client SPA (React 19)
        │
        ▼  (HTTP POST /api/v1/ai/chat)
Fastify BFF Middleware (`app.ts`)
        │
        ├─► Request Correlation ID Generation (`x-request-id`)
        ├─► Pino Structured Logger (`pino`)
        │
        ▼
AIGatewayService / Telemetry Service
        │
        └─► OpenTelemetry Tracer (`backend/src/telemetry/tracer.ts`)
             ├── Span Attributes: requestId, providerUsed, modelAlias
             ├── Metric Attributes: latencyMs, fallbackOccurred, tokens
             └── PII & Secret Masking Filter
```

## 3. Request Correlation (`x-request-id`)

To trace a single candidate request across microservice boundaries (React SPA $\rightarrow$ Fastify BFF $\rightarrow$ Python AI Microservice $\rightarrow$ AI Gateway), CareerCraft uses a request correlation ID (`x-request-id`).

1. **Generation**: If an incoming request lacks an `x-request-id` header, Fastify automatically generates a unique string identifier.
2. **Propagation**: The ID is attached to Fastify's request context (`req.id`), injected into OpenTelemetry spans, and forwarded in HTTP headers when the BFF calls internal services (such as `ai-workflow.routes.ts` forwarding to Python FastAPI).
3. **Response Header**: Returned to the client in the `x-request-id` HTTP response header.

## 4. OpenTelemetry Distributed Tracing

OpenTelemetry instrumentation measures execution latency and provider diagnostics across the AI Gateway and system endpoints.

### Implementation Source
* Tracer Initialization: [`backend/src/telemetry/tracer.ts`](file:///C:/Users/noham/.gemini/antigravity/scratch/CareerCraft/backend/src/telemetry/tracer.ts)
* Telemetry Service: [`backend/src/services/telemetry.service.ts`](file:///C:/Users/noham/.gemini/antigravity/scratch/CareerCraft/backend/src/services/telemetry.service.ts)

### Recorded Span & Metric Attributes
For every AI request, the telemetry service captures the following attributes:

| Attribute Name | Data Type | Description |
| :--- | :--- | :--- |
| `requestId` | `string` | Injected correlation ID (`x-request-id`). |
| `providerUsed` | `string` | Provider adapter invoked (`openrouter`, `ollama`, `mock`). |
| `modelAlias` | `string` | Target model alias (`career-fast`, `career-reasoning`, `career-private`). |
| `latencyMs` | `number` | Total round-trip execution latency in milliseconds. |
| `fallbackOccurred` | `boolean` | `true` if primary provider failed and fallback adapter executed. |
| `circuitState` | `string` | State of provider circuit breaker (`CLOSED`, `OPEN`, `HALF_OPEN`). |
| `usage.promptTokens` | `number` | Input token count reported by provider. |
| `usage.completionTokens`| `number` | Output token count generated by provider. |
| `usage.totalTokens` | `number` | Combined token consumption. |

## 5. Privacy & Telemetry Masking

To ensure candidate privacy and compliance with data protection standards, the telemetry layer enforces strict masking rules before emitting logs or spans:

### Excluded / Sanitized Data
* ❌ **User Credentials**: Passwords, authorization tokens (`Bearer ...`), and API keys are completely stripped.
* ❌ **Raw Resume Text**: Candidate CV bullets, contact numbers, and address details are excluded from span attributes.
* ❌ **Prompts & Responses**: Full text prompts and generated raw LLM outputs are logged only at `debug` level in non-production environments and omitted from telemetry attributes.

## 8. Current Limitations

* **Log Aggregation**: Logs are written to `stdout`/`stderr` in JSON format. Centralized log shipping (e.g. Datadog, Elasticsearch, Loki) must be configured at the container host layer.
* **Metric Persistence**: Telemetry metrics are evaluated in-memory during process runtime and are reset upon server restart.
